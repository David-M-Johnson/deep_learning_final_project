# Dense MASTER baselines: widths 64, 128 and 256

This directory is a cleaned copy of `david/reproduction/`, not a move or a new
architecture. All three versions use the same dense, market-gated model. Only
hidden width and output directory differ in the named configurations:

| Title | Config | Parameters |
| --- | --- | ---: |
| Dense MASTER — CSI300 — hidden width 64 | `configs/master_csi300_width64.json` | 66,177 |
| Dense MASTER — CSI300 — hidden width 128 | `configs/master_csi300_width128.json` | 212,353 |
| Dense MASTER — CSI300 — hidden width 256 | `configs/master_csi300_width256.json` | 775,041 |

Use [workspace setup](../README.md) to create an environment. This code does not
import or load runtime files from `david/` or `original_paper/`. Copied provenance
records retain historical paths; these are not dependencies.

## Training and evaluation

From this directory after setup:

```sh
../.venv/bin/python run_model.py --width 64 --dry-run
../.venv/bin/python run_model.py --width 64 --max-dates 5 --output runs/smoke-width64
../.venv/bin/python run_model.py --width 128
../.venv/bin/python run_model.py --width 256
```

Named launchers default to CPU, seed 0, up to 40 epochs, Adam at 1e-5,
dropout 0.5, four temporal heads, two stock heads and CSI300 gate beta 5.
`--device mps` or `--device cuda` can be selected explicitly if available.
Output directories must be new, preventing accidental overwrite. The model's
158 stock inputs, 63 market inputs, eight-observation history, market gate and
dense attention are preserved for every width. No sparse extension is included.

Training consumes the copied data in `../data/opensource/`. The target is
`close[t+5]/close[t+1]-1`. Renewed training labels are masked for invalid values,
trimmed by 2.5% in each tail and standardized within each date. Validation/test
retain all supplied inference stocks and mask invalid labels only for scoring.
Feature preprocessing is supplied by the upstream pickles; no statistics are
refitted on validation or test. See [data limitations](../data/README.md).

Training dates: January 2008–March 2020; validation: April–June 2020;
test: July 2020–December 2022. The runner excludes historical-context rows from
scoring and conservatively purges five final training/validation dates to avoid
forward labels crossing boundaries. The copied CSI300 run uses 2,974 training
and 54 validation dates. `--keep-boundary-labels` on `train.py` disables purging
and must be documented as a different protocol.

Stopping remains training MSE <= 0.95 or the epoch limit. Validation does not
select checkpoints. Only the latest checkpoint is saved; validation peaks may
not have retained weights. Automatic resume is not implemented. Checkpoints
include optimizer and CPU RNG states but not accelerator RNG for exact resume.

For checkpoint validation without retraining:

```sh
../.venv/bin/python evaluate.py saved_runs/csi300-width128/seed-0/last.pt \
  --split valid --max-dates 5 --output runs/reload-validation-width128
```

Use `--split test` without `--max-dates` only once checkpoint selection and
hyperparameters are frozen. Evaluation writes dated predictions, daily metrics,
aggregate metrics and data/checkpoint checksums. `train.py --evaluate-test` also
supports final test scoring; the named configurations leave it disabled.

## Copied experiment snapshots

`base_model/saved_runs/csi300-width{64,128,256}/` contains an independent copy of
each seed-0 checkpoint, history through that checkpoint's epoch, configuration,
environment and available provenance/data manifests. `snapshot.json` identifies
the captured epoch and checkpoint SHA256. These snapshots do not update as the
original runs continue; completion is not inferred. Predictions and summaries
that could be from a different epoch are intentionally regenerated by evaluation,
not mixed into a checkpoint snapshot.

To capture a later epoch, choose a new destination (from this directory):

```sh
../.venv/bin/python snapshot_run.py ../../david/reproduction/runs/csi300-width128 \
  saved_runs/csi300-width128-later
```

This optional copy command reads the original; normal training and figure
creation work entirely within `milestone_work/`.

## Figures and interpretation

See [figure commands](figures/README.md). All copied plotting scripts now write
to `base_model/figures/` by default. Histories and checkpoints are read-only inputs.
IC and RankIC are daily cross-stock Pearson and Spearman correlations averaged
over dates. ICIR and RankICIR divide mean daily correlation by population standard
deviation without annualization; undefined days are counted and excluded. These
are not classification accuracy or portfolio returns. Single-seed validation
curves and their best observed points cannot establish reproduction of the
paper's multi-seed held-out test results. No validated portfolio backtest is
implemented. The renewed dataset and default boundary purging are reproduction
deviations, even for width 256.

## Copy verification

November 15, 2026: all six destination data files matched SHA256 checksums of
original files. The three copied checkpoints passed recorded SHA256 checks and
strict reload into their corresponding model widths. Snapshot epochs are 35
(width 64), 25 (width 128), and 5 (width 256); these are not completion claims.
The model and MIT license copies match the originals byte for byte.

All three named commands passed dry-run checks. The copied synthetic smoke test
passed. A two-date, one-epoch width-256 run successfully trained and evaluated
using only the new data paths; a copied width-256 checkpoint also evaluated on
two validation dates. No real held-out test evaluation was performed. Comparison
and publication figures were regenerated locally, and the three-width comparison
and width-128 validation figures were visually inspected. Diagnostic plotting
with a separate matching history path also succeeded. Checks used the existing
compatible Python 3.11 environment; installation into a new milestone virtual
environment remains a user setup step. No full training was started here.
